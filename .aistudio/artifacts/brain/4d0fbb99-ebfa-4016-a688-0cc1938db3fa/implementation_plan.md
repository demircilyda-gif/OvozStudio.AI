# Обновление AI-Звонков: Realtime API, Пошаговый Мастер (Роль → Тема → Голос) и Гостевой Доступ

Архитектурный план исправления и оптимизации голосового агента: устранение причин сбоев звонков, снятие барьера авторизации при блокировке Firebase, внедрение пошаговой настройки и поддержка официальных голосов Gemini 3.8 Live API.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> **Подтверждённые решения (на основе ответов пользователя):**
> 1. **Режим по умолчанию**: **Realtime API** (`gemini-3.8-live` через WebSocket) с ультранизкой задержкой (~300 мс) вместо медленного пошагового синтеза. Клонированный голос Шохруха остаётся альтернативным режимом с понятной маркировкой скорости.
> 2. **Авторизация**: **Гостевой демо-режим** — звонки работают сразу без обязательного логина, что решает проблему с заблокированным аккаунтом Google Cloud / Firebase.
> 3. **Интерфейс настройки**: **Пошаговый мастер (1. Роль → 2. Тема → 3. Голос)** с привязкой контекста и быстрых тем к выбранной роли.

---

## 1. Overview & Core Concept

### 1.1. Выявленные причины, почему звонок не работал
1. **Блокировка авторизацией на клиенте и сервере**:
   - На клиенте в `handleStartCall` стояла проверка `if (!isAuthenticated) return;`. Из-за блокировки Google Cloud Console и API-ключа Firebase пользователь не мог войти в аккаунт, и звонок даже не начинался.
   - На сервере WebSocket `/api/live-call` требовал Bearer Token (`unauthorized: missing token`), отклоняя неавторизованные соединения с кодом 4401.
2. **Отсутствие обработки разрыва WebSocket**:
   - При ошибке или закрытии WebSocket клиент не уведомлял пользователя, а интерфейс «зависал» в состоянии вызова.
3. **Путаница в голосах и задержках**:
   - Клонированный голос Шохруха работал по цепочке `STT -> LLM -> TTS` с задержкой 2-4 секунды на реплику.
   - На Realtime API (`gemini-3.8-live`) выбор голоса был скрыт или не соответствовал официальным голосам Google, из-за чего роль и голос были рассинхронизированы.

### 1.2. Решение
- Сделать **Realtime API** основным режимом с мгновенной реакцией.
- Встроить поддержку 5 официальных голосов Gemini Live API:
  - **Puck** (Энергичный, живой мужской голос — Шохрух по умолчанию)
  - **Charon** (Глубокий баритон — солидный риелтор Жасур)
  - **Aoede** (Тёплый, харизматичный женский голос — риелтор Мадина)
  - **Kore** (Мягкий, спокойный женский голос — консультант Азиза)
  - **Fenrir** (Уверенный, авторитетный мужской голос — эксперт Улугбек)
- Разрешить гостевые звонки в один клик: сервер и клиент генерируют безопасный гостевой сеанс, если Firebase заблокирован или пользователь не вошёл.
- Построить удобный пошаговый мастер: **Шаг 1: Роль** → **Шаг 2: Тема** → **Шаг 3: Голос**.

## 3. Technical Architecture & Sequences

```
[ Пользователь в браузере ]
           │
           ├─ 1. Клик "Начать звонок" (Гостевой сеанс или JWT)
           │
           ▼
[ WebSocket /api/live-call?token=guest_or_jwt ]
           │
           ├─ Если token отсутствует/невалиден: создаётся гостевой guest_uid
           │
           ▼
[ Gemini 3.8 Live API WebSocket ] ── model: "gemini-3.8-live"
           │                       voiceConfig: Puck / Charon / Aoede / Kore / Fenrir
           │                       systemInstruction: роль риелтора / подкаста / консультанта
           ▼
[ Двусторонний аудиопоток 24kHz PCM ]
           │
           ├─ Микрофон (16kHz PCM Base64) ──> Gemini Live
           └─ Gemini Live (24kHz PCM) ──────> Браузер WebAudio (AudioContext)
```

## 4. Implementation Steps

1. **Сервер (`server.ts`)**:
   - В `server.on("upgrade")` для `/api/live-call`: разрешить подключение гостевых пользователей, если токен отсутствует или Firebase временно недоступен (`guest-session-...`).
   - Синхронизировать голоса Live API с точными официальными именами (`Puck`, `Charon`, `Aoede`, `Kore`, `Fenrir`).
   - Привязать системные инструкции Live API строго к выбранной роли (`tashkent_real_estate`, `live_cohost`, `caller_in_air`, `business_consultant`).
   - Добавить обработку ошибок соединения Live API с отправкой информативного `type: "error"` клиенту.

2. **Клиентский компонент (`VoiceAgentTab.tsx` & `LiveCallCard.tsx`)**:
   - Перестроить интерфейс в пошаговый мастер: **Шаг 1: Роль → Шаг 2: Тема → Шаг 3: Голос**.
   - Добавить селектор официальных голосов Realtime API с предпрослушиванием и описанием тембра.
   - Убрать блокировку `if (!isAuthenticated) return;` — разрешить мгновенный звонок в гостевом режиме.
   - Обработать закрытие и ошибки WebSocket в `ws.onclose` и `ws.onerror`, чтобы вызов корректно сбрасывался или переключался на резервный режим.

3. **Верификация**:
   - Проверка компиляции через `tsc --noEmit` и `compile_applet`.
   - Проверка WebSocket соединения и тестового звонка.
